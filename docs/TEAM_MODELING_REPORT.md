# LG Aimers 제구 성공 확률 예측: 전처리·피처 엔지니어링·모델 비교 보고서

## 1. 보고서 목적

이 보고서는 제공된 투구 데이터와 Trackman 데이터를 사용해 다음 투구의 `control_success` 확률을 예측한 과정과 결과를 팀원이 재현할 수 있도록 설명합니다. 단순히 최종 점수만 나열하지 않고 다음 내용을 구분합니다.

- 모델 실행에 필요한 최소 전처리
- V1 전체 전처리와 과거 기록 피처
- 추가 row-wise 피처 엔지니어링
- HistGradientBoosting, XGBoost, CatBoost, LightGBM 비교
- 기존 HGB와 새 4모델 비교 결과가 다르게 나온 이유
- 현재 채택 후보와 다음 검증 계획

## 2. 문제와 평가 방식

목표값은 각 투구의 제구 성공 여부인 `control_success`입니다. 모델은 0 또는 1을 직접 맞히는 것이 아니라 성공 확률을 출력합니다. 주 평가 지표는 Brier Score입니다.

```text
Brier = mean((예측확률 - 실제값)^2)
```

Brier Score는 낮을수록 좋습니다. AUC는 성공 투구를 실패 투구보다 높게 정렬하는 능력을, ECE는 예측 확률과 실제 성공률의 보정 오차를 확인하는 보조 지표로 사용했습니다.

검증 데이터는 2024 시즌 253,507행이며, 학습 데이터는 2024 미만 시즌 1,221,585행입니다. 2024는 최종 성능 평가에만 사용한다는 원칙을 적용했습니다.

## 3. 전체 데이터 처리 흐름

```text

        ↓

        ↓
현재 투구 상황 피처 생성
        ↓
예측 시즌 이전 기록만 사용한 투수 이력 피처
        ↓

        ↓

        ↓

        ↓

        ↓

```

## 4. 전처리 전후 비교의 정확한 의미

### 4.1 원본 최소처리: 47개

`raw_minimal`은 공식 원본 열 47개를 사용합니다.

- 숫자형 38개: 숫자 변환, 무한대 값을 결측치로 처리, `float32` 변환
- 범주형 9개: 문자열 변환, 결측을 `__MISSING__` 범주로 처리
- `row_id`와 정답 `control_success`는 입력에서 제외

scikit-learn 모델은 임의 문자열을 그대로 처리할 수 없으므로 완전한 무처리는 불가능합니다. 따라서 이 실험은 “모델 실행에 필수인 처리만 수행한 원본 피처”입니다.

### 4.2 모델별 입력 변환

- LightGBM: 범주형을 category로 유지하고 숫자 결측은 NaN으로 전달
- CatBoost: 범주형 문자열과 범주 인덱스를 직접 전달
- HGB/XGBoost: 범주형을 학습 데이터 기준 빈도 인코딩하고 숫자 결측을 학습 중앙값으로 대체
- 모든 인코더와 중앙값은 학습 구간에서만 적합해 검증 정보가 들어가지 않게 함

## 5. V1 155개 피처

### 5.1 공식 원본 피처: 47개

경기 시점, 이닝, 볼카운트, 아웃카운트, 점수, 주자, 승리확률, LI, 공식 `asof_` 비율, 투수·타자·팀 ID, 투타 손, 베이스 상태 등을 사용했습니다.

### 5.2 현재 행 파생 피처: 23개

- 볼카운트: `count_state`, 투수 우세, 타자 우세, 2스트라이크, 3볼, 풀카운트
- 주자: 주자 존재, 득점권 주자, 만루
- 점수·이닝: 동점, 점수 차 절댓값, 접전, 후반, 연장, ABS 시대 구분
- 범주 조합: 이닝 구간, 좌우 상대 유형
- 표본 크기: `asof_*_n`의 `log1p` 변환과 결측 여부

### 5.3 과거 정답 기반 투수 이력 피처: 29개

예측 시즌보다 이전 시즌의 `control_success`만 사용했습니다.

- 투수 통산 성공률과 표본 수
- 직전 시즌 성공률과 표본 수
- 투수×볼카운트, 투수×주자, 투수×득점권, 투수×타자 손 성공률
- 최근 20·50·100구 성공률과 표본 수
- 마지막 관측 시즌과 시즌 공백
- 직전 시즌 대비 통산 변화, 최근 50구 대비 통산 변화

표본이 적은 그룹의 극단적인 성공률을 막기 위해 smoothing을 적용했습니다.

```text
smoothed_rate = (성공 수 + smoothing × prior) / (표본 수 + smoothing)
```

기본 smoothing 강도는 50이며 최근 투구 피처는 20입니다.

### 5.4 Trackman 피처: 56개

투수 ID-Trackman ID 매핑에서 신뢰등급이 `확정` 또는 `높음`인 투수만 연결했습니다. 예측 시즌보다 이전 시즌 데이터만 사용했습니다.

- 구속, 회전수, 수직·수평 무브먼트, 익스텐션, 릴리스 높이·좌우 위치, 홈플레이트 도달 속도
- 각 항목의 통산 평균·표준편차
- 직전 시즌 평균·표준편차
- 패스트볼·브레이킹·오프스피드·기타 구종 비율
- 직전 시즌과 그 이전 기간의 변화량
- 매핑 순도·등급·수용 여부, 마지막 관측 시즌, 시즌 공백, 결측 여부

## 6. v1_all 194개 피처

V1 155개에 39개의 row-wise 블록을 추가했습니다.

### 6.1 공식 asof 추세·대조: 13개

- 최근 1경기와 3·5경기의 성공률 차이
- 최근 1경기와 3·5경기의 middle 비율 차이
- 전체 성공률과 최근 5경기 성공률 차이
- 투수와 타자의 성공률·middle 비율 차이
- 스트라이크 비율과 볼 비율 차이
- 추세 계산에 실제로 존재한 소스 개수

현재 행의 정답은 사용하지 않고 제공된 사전 시점 `asof_` 열만 조합했습니다.

### 6.2 상황·압박 피처: 11개

- `log1p(LI)`, 고레버리지 여부
- 후반 접전, 후반 접전 고레버리지
- 압박 점수
- 2아웃 득점권, 2아웃 미만 만루
- 주자 수×잔여 아웃 압박
- 풀카운트×LI
- 베이스-아웃 상태, 카운트-베이스-아웃 결합 범주

### 6.3 구종 구성 피처: 8개

- 구종 구성 엔트로피
- 최다·최소 구종 비율
- 패스트볼-브레이킹, 패스트볼-오프스피드, 브레이킹-오프스피드 차이
- 관측된 구종 비율 합과 구종 정보 존재 여부

### 6.4 신뢰도 피처: 7개

표본 수 `n`을 다음 식으로 0~1 사이 신뢰도로 바꿨습니다.

```text
reliability = n / (n + strength)
```

투수·타자 asof, 구종 구성, 투수 이력, Trackman의 신뢰도를 만들고, 신뢰도로 가중한 투수-타자 차이와 사용 가능한 정보원 개수를 추가했습니다.

## 7. 타자 위협도 교차피처: 6개

타자 위협도는 장타력의 직접 지표가 아니라 “이 타자를 상대할 때 제구 성공이 어려웠던 정도”의 대리변수입니다.

```text
batter_control_threat_proxy = 1 - asof_batter_success_rate
```

- `hand_match`: 투수와 타자의 손이 같은지
- `success_interact`: 투수 성공률×타자 상대 성공률
- `reverse_x_middle`: 투수 reverse 비율×middle 비율
- `threat_x_reverse`: 위협도 대리변수×reverse 비율
- `threat_x_middle`: 위협도 대리변수×middle 비율
- `threat_x_ball`: 위협도 대리변수×볼 비율

XGBoost 최종 모델에서 이 6개 피처의 gain 중요도 합은 약 23.3%였습니다. `success_interact`가 17.86%로 전체 1위였고 `threat_x_reverse`가 3.79%로 전체 4위였습니다. 다만 gain 중요도는 인과효과가 아니며, 실제 채택 판단은 동일 조건 Brier 비교로 해야 합니다.

## 8. 비교 모델

### HistGradientBoosting

대규모 수치형·인코딩된 범주형 데이터를 bin 단위로 학습합니다. 전처리된 표 형식 데이터에 강하고 scikit-learn 안에서 안정적으로 실행됩니다. GPU를 사용하지 않으며 피처 중요도를 기본 제공하지 않는다는 단점이 있습니다.

### XGBoost

`tree_method=hist`를 사용했습니다. 비선형 상호작용 탐색에 강하며 위협도 교차피처의 효과가 가장 크게 나타났습니다. HGB보다 빠른 실행시간도 장점입니다.

### LightGBM

범주형과 결측을 직접 처리하고 학습 속도가 빠릅니다. 기존 정상 실행에서는 139~213회의 반복 수가 선택됐으나 새 2023 단일 시즌 튜닝에서는 10~11회로 줄어 과소학습됐습니다.

### CatBoost

범주형을 직접 처리하는 장점이 있으나 새 비교에서는 반복 수가 1회로 선택됐고 예측 표준편차가 약 0.0012에 불과했습니다. 현재 결과는 모델의 충분한 성능을 나타내는 결과가 아닙니다.

| 모델 | 원본 최소처리 | v1_all | v1_all+위협도 | 해석 |
|---|---:|---:|---:|---|

| LightGBM | 0.250950 | 0.250928 | 0.250774 | 위협도 추가가 0.000155 개선 |
| CatBoost | 0.249934 | 0.249919 | 0.249934 | 위협도 추가 후 0.000015 악화 |

이 표에서는 HGB가 전처리 효과가 가장 컸고, XGBoost가 위협도 교차피처의 효과를 가장 크게 활용했습니다.

## 10. 새 4모델 표를 그대로 최종 순위로 쓰면 안 되는 이유

공정 비교 프리셋은 2019~2022로 학습하고 2023에서 반복 수를 선택한 뒤 2019~2023으로 재학습했습니다. 2024를 반복 수 선택에 사용하지 않았다는 점은 올바릅니다. 하지만 2023 한 시즌만으로 반복 수를 결정하면서 다음과 같이 과도하게 작은 값이 선택됐습니다.

| 모델 | 선택 반복 수 | 결과상 문제 |
|---|---:|---|
| CatBoost | 1 | 거의 상수에 가까운 확률 출력 |
| HGB | 4 | 기존 350회 대비 심각한 과소학습 |
| LightGBM | 10~11 | 기존 정상 실행 139~213회보다 지나치게 작음 |
| XGBoost | 11~25 | 네 모델 중 상대적으로 덜 손상됨 |

학습 구간의 성공률은 약 0.5316이고 2024 검증 성공률은 약 0.4861로 4.55%p 차이가 납니다. 연도별 분포 변화가 큰 상황에서 2023 하나의 최적 반복 수가 2024에 그대로 일반화되지 않았습니다.

## 11. 현재 확인된 최고 후보

`v1_all__hist_gbdt`가 현재 실제 실행 결과 중 최고입니다.

| 모델 | Brier | AUC | ECE | 반복 수 | 시간 |
|---|---:|---:|---:|---:|---:|
| 기존 HGB v1_all | 0.248263 | 0.546055 | 0.008865 | 350 | 624초 |
| XGBoost v1_all+위협도 | 0.249378 | 0.543064 | 0.025402 | 25 | 219초 |

HGB는 XGBoost보다 Brier가 0.001115 낮고, AUC와 ECE도 더 좋았습니다. XGBoost는 약 2.85배 빨라 시간 대비 후보로 가치가 있습니다.

다만 과거 HGB 결과와 새 XGBoost 결과는 데이터 행 수와 2024 성공률이 같지만 파일 서명은 저장 시각 변경 등으로 달랐습니다. 최종 확정 전에는 v1.4의 동일 데이터 서명 아래에서 두 모델을 다시 실행하는 것이 안전합니다.

## 14. 누수와 규정 점검

- 현재 행의 `control_success`는 입력 피처로 사용하지 않음
- 직접 계산한 이력과 Trackman 집계는 `season < 예측 season` 조건을 적용
- 2024는 최종 검증용으로 분리
- 공식 `asof_` 열은 사전 시점 정보라는 대회 정의를 전제로 사용
- 외부 선수 성적이나 외부 야구 통계는 추가하지 않음
- 원본 대회 데이터와 검증 예측은 팀 내부에서만 공유 권장

대회 공지에서 공식 `asof_` 열이나 제공 Trackman·매핑의 사용 범위를 별도로 제한한다면 해당 공지를 최우선으로 적용해야 합니다.

6. 동일 데이터 서명인지 확인
7. Brier, AUC, ECE, 반복 수, 예측 평균·표준편차 확인
8. 최고 후보의 `validation_predictions.csv.gz` 보존
9. 여러 시즌 안정성 검증 후 최종 제출 모델 확정

## 16. 추가 full 검증: Compact A–E + CatBoost

같은 2019~2023 학습, 2024 검증 분할에서 HGB와 CatBoost 각각에 다섯 단계 피처
축소를 적용했습니다. 전체 194개, 선수 ID 제거 192개, Trackman 제거 137개, 핵심
88개, 핵심+대표 Trackman 107개입니다.

최종 1위는 HGB Trackman 제거 137개로 Brier `0.24817527`이었습니다. 전체 피처보다
29.4% 작고 약 30.7% 빠르면서 점수도 `0.00003681` 낮았습니다. 가장 작은 HGB
88개는 Brier `0.24829631`로 전체보다 `0.00008423`만 악화되어 사전 허용선 안입니다.

CatBoost 자체 최고는 107개 E의 `0.24978767`이지만, 2023 튜닝에서 반복 수가 3회로
선택되어 HGB보다 과소학습됐습니다. 따라서 현재 최종 추천은 성능 우선 HGB 137개,
연산·해석 우선 HGB 88개입니다. 상세 표와 정확한 열 목록은
`docs/COMPACT_FEATURE_EXPERIMENT.md`를 참고합니다.
